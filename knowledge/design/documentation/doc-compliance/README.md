# Documentation Compliance

Approaches to automated and manual compliance checking for technical documentation. This topic covers quality criteria, structural and content-level checks, tooling, and coverage analysis.

## Atomic Notes

| File | Description |
|---|---|
| [diataxis-quality.md](diataxis-quality.md) | Using the Diataxis quality model as compliance criteria — functional quality (accuracy, completeness, consistency, usefulness, precision) and deep quality (flow, beauty, anticipating the user) |
| [structural-compliance.md](structural-compliance.md) | Checking that a docs site has all required sections, files, valid frontmatter, and resolvable cross-links |
| [content-compliance.md](content-compliance.md) | Verifying correct Diataxis quadrant classification, appropriate language patterns, and stale content detection |
| [tooling.md](tooling.md) | Tool landscape for automated compliance checking: Vale, markdownlint, lychee, write-good, alex, and doc coverage tools |
| [coverage-analysis.md](coverage-analysis.md) | Measuring what is documented vs what exists in code — API endpoints, configuration options, CLI flags |
