# Skill Metadata Taxonomy

## Queryable Registry Pattern

While there is no built-in query endpoint for the skill catalogue, the `metadata` frontmatter field provides the foundation for a queryable registry.

### Metadata Fields in SKILL.md

The `metadata` field is a `map[string,string]` in the SKILL.md frontmatter. It accepts arbitrary key-value pairs for classification, routing, and discovery purposes.

```yaml
---
name: pr-review
description: Automated code review with inline suggestions
metadata:
  audience: developers
  workflow: github
  category: review
  tags: code-review, github, automation
---
```

### Recommended Metadata Taxonomy

| Key | Type | Purpose | Example Values |
|---|---|---|---|
| `audience` | string | Who uses this skill | `developers`, `maintainers`, `ops`, `qa`, `all` |
| `workflow` | string | The workflow domain | `github`, `ci`, `deploy`, `local`, `review` |
| `category` | string | Functional classification | `review`, `release`, `scaffold`, `test`, `docs`, `config` |
| `tags` | string | Comma-separated keywords for faceted search | `code-review, ruff, python` |
| `complexity` | string | Difficulty or risk level | `beginner`, `intermediate`, `advanced` |
| `language` | string | Primary programming language | `python`, `typescript`, `rust`, `any` |
| `plugin` | string | Associated plugin or MCP server name | `@opencode/plugin-github`, `none` |
| `agent` | string | Recommended agent type for this skill | `general`, `kb-architect`, `explore` |

### Using Metadata for Discovery

Without a built-in query API, metadata serves as documentation for human readers and as routing hints for agent developers. Typical use cases:

1. **Agent routing**: An agent's system prompt can reference metadata patterns to select skills. For example, a CI agent may be told to prefer skills with `workflow: ci` or `workflow: deploy`.
2. **Skill directory indexing**: A repo's skills README or catalogue page can be generated by extracting `metadata` from each SKILL.md frontmatter.
3. **Permission scoping**: Permission rules in `opencode.json` can reference skill name patterns (glob-based) that align with metadata categories.

### Metadata Conventions

- Use lowercase for all metadata values to enable case-insensitive matching.
- Use kebab-case for multi-word values (`code-review`, not `code_review` or `Code Review`).
- Tags in the `tags` field should use kebab-case and should not duplicate the `name` or `category`.
- Avoid changing metadata values after publication if other systems depend on them for routing.
