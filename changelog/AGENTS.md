# Changelog Section

Simple record of what changed in this repository. Each entry is a single markdown file.

## Naming Convention

```
{date}-{title}-changelog.md
```

Examples:
- `2026-07-14-restructure-configs-changelog.md`
- `2026-07-14-update-k3s-version-changelog.md`
- `2026-07-14-add-node-extra-config-changelog.md`

## Content Format

A plain markdown file with:

```markdown
# {date} — {Title}

What changed and why. Free-form, no frontmatter required.

## Changes

- Summary of each change
- Links to relevant files or configs

## Related

- links to related_knowledge or related_configs paths if applicable
```

No frontmatter or structured metadata required — keep it simple.
