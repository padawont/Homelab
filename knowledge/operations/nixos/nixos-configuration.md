# NixOS Configuration

## /etc/nixos layout

The main configuration directory on a NixOS system is `/etc/nixos/`. It typically contains:

| File | Purpose | Auto-generated? |
|---|---|---|
| `configuration.nix` | Main system configuration | Initial generation only |
| `hardware-configuration.nix` | Hardware-specific settings (disks, kernel modules) | Yes, every `nixos-generate-config` |
| `flake.nix` | Flake entry point (optional, flake-based setups) | Optional |
| `flake.lock` | Locks flake input versions | Yes, on first flake build |

### configuration.nix

The primary file where system settings are declared. A minimal example:

```nix
{ config, pkgs, ... }: {
  imports = [
    ./hardware-configuration.nix
  ];

  boot.loader.systemd-boot.enable = true;
  boot.loader.efi.canTouchEfiVariables = true;

  networking.hostName = "nixos";
  networking.networkmanager.enable = true;

  services.openssh.enable = true;

  users.users.alice = {
    isNormalUser = true;
    extraGroups = [ "wheel" "networkmanager" ];
  };

  environment.systemPackages = with pkgs; [
    vim
    git
    htop
  ];

  system.stateVersion = "24.11";
}
```

Common sections in `configuration.nix`:

| Section | Purpose |
|---|---|
| `boot.*` | Bootloader, kernel modules, initrd |
| `networking.*` | Hostname, interfaces, firewall, WiFi |
| `services.*` | Enable and configure system services (sshd, nginx, postgresql, etc.) |
| `users.*` | User accounts, groups, passwords, SSH keys |
| `environment.*` | System-wide packages, shell configuration, session variables |
| `system.*` | State version, auto-upgrade, garbage collection |
| `nix.*` | Nix daemon settings, trusted users, binary caches |

### hardware-configuration.nix

Generated by `nixos-generate-config` based on currently mounted filesystems. Contains:

```nix
{ config, lib, pkgs, modulesPath, ... }: {
  imports = [ (modulesPath + "/installer/scan/not-detected.nix") ];

  boot.initrd.availableKernelModules = [ "xhci_pci" "ahci" "nvme" ];
  boot.initrd.kernelModules = [ ];
  boot.kernelModules = [ "kvm-amd" ];
  boot.extraModulePackages = [ ];

  fileSystems."/" = {
    device = "/dev/disk/by-uuid/1234-5678";
    fsType = "ext4";
  };

  fileSystems."/boot" = {
    device = "/dev/disk/by-uuid/ABCD-EF01";
    fsType = "vfat";
  };

  swapDevices = [ { device = "/dev/disk/by-uuid/9876-5432"; } ];
}
```

**Do not edit `hardware-configuration.nix` manually** — it is overwritten by `nixos-generate-config`. Override hardware settings in `configuration.nix` instead.

## Options system

NixOS configuration is built on a module system with typed options.

### Option declaration

Modules declare options using `lib.mkOption`:

```nix
{ config, lib, pkgs, ... }:
{
  options.services.my-service.enable = lib.mkEnableOption "my-service";

  options.services.my-service.port = lib.mkOption {
    type = lib.types.port;
    default = 8080;
    description = "Port to listen on";
  };
}
```

### Common option types

| Type | Nix representation | Example |
|---|---|---|
| `types.bool` | `true` / `false` | `services.openssh.enable = true` |
| `types.str` | `"hello"` | `networking.hostName = "myserver"` |
| `types.int` | `42` | `services.my-service.port = 8080` |
| `types.port` | `8080` | Validated port number (0-65535) |
| `types.path` | `./some/file` | Filesystem path |
| `types.package` | `pkgs.hello` | A Nix package |
| `types.listOf t` | `[ a b c ]` | List of type `t` |
| `types.attrsOf t` | `{ name = value; }` | Attribute set of type `t` |
| `types.submodule` | `{ ... }` | Nested option set |

### Overriding with priority functions

- `lib.mkForce value` — force a value, overriding lower-priority definitions
- `lib.mkDefault value` — set a default (lower priority than direct assignment)
- `lib.mkIf condition value` — conditionally apply a value

## Imports pattern

Configurations can be split across multiple files using `imports`:

```nix
{ config, pkgs, ... }: {
  imports = [
    ./hardware-configuration.nix
    ./modules/development.nix
    ./users/alice.nix
    ./services/monitoring.nix
    (import ./generated/net-config.nix)
  ];
}
```

Each imported file follows the same `{ config, pkgs, ... }: { ... }` pattern.

## Flakes

Flakes provide a way to lock dependencies and compose configurations from multiple sources.

### flake.nix structure

```nix
{
  description = "My NixOS configuration";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-24.11";
    nixos-hardware.url = "github:NixOS/nixos-hardware";
    sops-nix.url = "github:Mic92/sops-nix";
    sops-nix.inputs.nixpkgs.follows = "nixpkgs";
  };

  outputs = { self, nixpkgs, sops-nix, ... }@inputs: {
    nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./configuration.nix
        sops-nix.nixosModules.sops
      ];
      specialArgs = { inherit inputs; };
    };
  };
}
```

### Inputs

Declare dependencies:
- `nixpkgs` — the Nix packages collection (required)
- `nixos-hardware` — hardware-specific configs for known devices
- `sops-nix`, `agenix` — secrets management
- `disko` — disk partitioning tool
- `home-manager` — user package management

### Outputs

Define what the flake produces:
- `nixosConfigurations.<name>` — NixOS system configurations
- `packages.<system>.<name>` — buildable packages
- `devShells.<system>.<name>` — development shells
- `checks.<system>.<name>` — CI checks
- `formatter.<system>` — code formatter

### Flake vs classic workflow

| Aspect | Classic (channels) | Flakes |
|---|---|---|
| Configuration source | `nixos-rebuild switch` | `nixos-rebuild switch --flake .#host` |
| Dependency pinning | `nix-channel --update` | `flake.lock` (locked) |
| Multiple nixpkgs | Not supported | Multiple inputs with different versions |
| Reproducibility | Channel-dependent | Deterministic via lock file |
| Adoption | Legacy | Modern, recommended for new setups |

## Rebuild workflow

NixOS provides `nixos-rebuild` for applying configuration changes:

| Command | Effect |
|---|---|
| `nixos-rebuild switch` | Activate new config and add to boot menu |
| `nixos-rebuild test` | Activate now, do not add to boot menu |
| `nixos-rebuild boot` | Set as default for next boot, do not activate now |
| `nixos-rebuild dry-activate` | Show what would change, do nothing |
| `nixos-rebuild build` | Build new config, do not activate |
| `nixos-rebuild switch --flake .#host` | Flake-based: build and switch to host config |
| `nixos-rebuild switch --upgrade` | Update nixpkgs channel before building |
| `nixos-rebuild switch --rollback` | Revert to previous generation |

### What happens during a switch

1. Evaluate the new NixOS configuration
2. Build the system closure (download/build all dependencies)
3. Create a new generation symlink in `/nix/var/nix/profiles/system`
4. Run activation script:
   - Set up `/etc` files from the Nix store
   - Restart/reload changed systemd services
   - Update bootloader entries
5. If successful: boot menu now includes the new generation
6. If failed: the system remains on the current generation (atomic)
