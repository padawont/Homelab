# kiwix-serve Configuration

## Container Image

The official kiwix-serve image is published at:

```
ghcr.io/kiwix/kiwix-serve
```

Tags: `latest`, `3.x.x` (semver). The image is multi-arch (amd64, arm64, arm32v7). Current release: 3.8.2 with libzim 9.5.0.

> **Source**: [kiwix-serve Docker Image — GitHub](https://github.com/kiwix/kiwix-tools/blob/main/docker/server/README.md)

## Port

kiwix-serve listens on TCP port **8080** by default. This is configurable via the `PORT` environment variable.

## Volume Mount

ZIM files must be placed at `/data` inside the container. The directory is declared as a Docker `VOLUME` in the image.

## Command / Entrypoint

The image uses ENTRYPOINT `["/usr/bin/dumb-init", "--", "/usr/local/bin/start.sh"]`. The `start.sh` script runs `kiwix-serve --port=$PORT` at runtime (defaults to 8080). ZIM file paths are passed via CMD/args:

```
docker run ghcr.io/kiwix/kiwix-serve /data/file.zim
```

In Kubernetes, use `args:` (not `command:`) to pass ZIM files:

```yaml
args:
- /data/wikipedia_en_all_maxi_2025-08.zim
```

## ZIM Format Compatibility

kiwix-tools 3.8.2 with libzim 9.5.0 (official Docker image) supports ZIM format v4.0 but does NOT support ZIM v4.6 files (mid-2025+). To serve v4.6 files, a nightly kiwix-serve binary with libzim 9.8.1+ is required.

In the homelab, this is handled by mounting a nightly binary from hostPath and using a library XML file generated by `kiwix-manage`.

| ZIM File | libzim 9.5.0 | libzim 9.8.1 | Approx Size |
|---|---|---|---|
| `wikipedia_en_all_maxi_2025-08.zim` | Incompatible (v4.6) | Compatible | ~111 GB |
| `wikipedia_en_all_maxi_2026-02.zim` | Incompatible (v4.6) | Compatible | ~115 GB |
| `wikipedia_en_all_mini_2026-06.zim` | Incompatible (v4.6) | Compatible | ~12 GB |

## Command-Line Flags

Full reference at [kiwix-tools.readthedocs.io](https://kiwix-tools.readthedocs.io/en/stable/kiwix-serve.html):

| Flag | Description |
|---|---|
| `--port`, `-p` | TCP port (default 80 CLI, 8080 in Docker) |
| `--address`, `-i` | Bind address |
| `--urlRootLocation`, `-r` | URL path prefix |
| `--threads`, `-t` | Number of concurrent request threads |
| `--library`, `-l` | Use library XML file instead of direct ZIM paths |
| `--skipInvalid`, `-k` | Start even if ZIM files are invalid (skips them) |
| `--verbose`, `-v` | Print debug log to STDOUT |
| `--daemon`, `-d` | Detach from main process |
| `--monitorLibrary`, `-M` | Reload library XML on changes |
| `--searchLimit`, `-s` | Max ZIM files in fulltext search |
| `--ipConnectionLimit`, `-L` | Max concurrent connections per IP |
| `--customIndex`, `-c` | Custom welcome page HTML |
| `--blockexternal`, `-b` | Block external resource navigation |

## Performance

The following are empirical recommendations (not documented by upstream):

- **Minimum RAM**: 256 MB (for small ZIM files under 1 GB)
- **Recommended RAM**: 1–2 GB (for full Wikipedia ~115 GB ZIM)
- **CPU**: single core sufficient; multi-core helps with concurrent requests
- **Threads**: Each additional thread consumes ~50 MB RAM. Default 4 threads is appropriate for most deployments.

## Health Checks

kiwix-serve responds on `GET /` with HTTP 200 when running. Use this for liveness and readiness probes.

## ZIM File Management

- kiwix-serve detects ZIM files at startup; files added or removed while running require a restart
- Multiple ZIM files in the same directory work — kiwix-serve presents a library page listing all available content
- The container only needs **read** access to the ZIM files — no write permission required after initial provisioning

## Homelab Deployment

The homelab deployment on node-1's K3s cluster uses the following configuration (defined in `configs/node-main/kubernetes/kiwix.yaml`):

| Parameter | Value |
|---|---|
| Namespace | `kiwix` |
| Deployment replicas | 1 |
| Container image | `alpine:3.20` (hostPath binary for kiwix-serve) |
| kiwix-serve binary | Nightly build (2026-07-18, libzim 9.8.1) at `/opt/kiwix-serve` on node-1 host |
| ZIM loading method | Library XML at `/opt/kiwix-library.xml` (generated by `kiwix-manage`) |
| Container port | 8080 |
| PVC name | `kiwix-data` |
| PVC storage | 200Gi (Longhorn `longhorn` storage class) |
| Resource requests | CPU 200m, memory 256Mi |
| Resource limits | CPU 1000m, memory 2Gi |
| Service type | LoadBalancer |
| LoadBalancer IP | 192.168.111.101 |
| Service port | 80 → 8080 |
| Liveness probe | GET /, delay 30s, period 20s |
| Readiness probe | GET /, delay 15s, period 10s |
| ZIM file | `wikipedia_en_all_maxi_2025-08.zim` (~111 GB, ZIM v4.6) |

**Note:** The official `ghcr.io/kiwix/kiwix-serve:3.8.2` image (libzim 9.5.0) does not support ZIM v4.6 files. The cluster uses a nightly kiwix-serve binary (libzim 9.8.1) mounted via `hostPath`. The binary is installed at `/opt/kiwix-serve` and the library XML at `/opt/kiwix-library.xml`. The Deployment uses `alpine:3.20` as the base image and runs the kiwix-serve binary with `--library /opt/kiwix-library.xml`.

ZIM files are initially loaded via a copy Job (`configs/node-main/kubernetes/kiwix-copy-job.yaml`) that uses a `busybox` container to copy files from the node-1 host path `/home/nixos/kiwix-zim` to the PVC at `/data`.
